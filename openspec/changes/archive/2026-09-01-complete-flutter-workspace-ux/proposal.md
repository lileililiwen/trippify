# Proposal: Complete Flutter workspace UX

## Problem

The app exposes many feature screens but only a small subset is reachable through the primary shell. Creator, admin, tenant, notifications, imports, licenses, and self-hosted operations lack a coherent workspace hierarchy. The shell also duplicates sign-out and has mobile layout risks.

## Scope

Create role-aware workspace navigation, consistent back/deep-link behavior, responsive layouts, public guide merchandising, and accessible loading/error/empty actions. This excludes new backend capabilities and visual rebranding.

## Acceptance

Traveler, creator, administrator, and tenant users can reach their authorized workflows from predictable navigation; unauthorized routes explain access; narrow and wide layouts remain usable; public guides communicate value and purchase state.
